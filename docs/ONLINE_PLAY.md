# 益智對戰：玩法設計與線上架構

更新：2026-10-26（Claude研究與設計，交Codex實作）。目標：在20款小遊戲中加入好玩、能和朋友對戰的益智遊戲，同時守住兒童安全、離線可玩與低成本。本文件的新遊戲都是**候選**，放進企劃矩陣前請Justin確認；候選名額可優先用[GAME_DESIGN.md](GAME_DESIGN.md)「玩法重疊」那幾組空出來的位置。

## 範圍決定（2026-10-26 Justin）

**先求輕量、簡單、快；商業模式還沒定，不先投入後端。** 這一輪只做不需要伺服器的L0（挑戰連結、每日題目）與L1（同裝置雙人、對電腦）。L2好友即時對戰與L3公開配對**暫緩**：Cloudflare技術上做得到、免費額度也夠（見下方「線上架構」），但要等確認有玩家、商業模式也定了再決定。下方的線上架構章節保留作為日後參考，現在不要實作。

規則套件仍照「瀏覽器與伺服器共用的純函式」來寫，日後要加線上對戰時不必重寫。

## 設計原則

1. **對戰要好玩，輸了也想再來**：一局90秒到5分鐘；落後的人有翻盤機會（連鎖反擊、最後一回合加倍）；結算先講「你做得好的地方」，再講勝負。
2. **先跟認識的人玩**：好友房間碼、同一台裝置、和電腦對戰，優先於和陌生人配對。公開配對最後才做，而且要先過安全審查。
3. **不需要網路也能玩**：每款對戰遊戲都要有「對電腦」與「同裝置雙人」模式；線上只是多一種對手。伺服器掛掉或免費額度用完時，自動退回對電腦。
4. **零個資**：不建帳號、不輸入名字、沒有文字或語音聊天。暱稱從固定的怪獸名稱表隨機產生，互動只用預設貼圖。
5. **規則只寫一份**：所有對戰規則寫成純函式套件，瀏覽器和伺服器共用同一份，伺服器才能驗證結果、防作弊。這沿用AGENTS.md「規則放在可測試的純函式」的規定。

## 分層：從零後端做起

| 層級 | 玩法 | 需要伺服器 | 先做哪款 |
| --- | --- | --- | --- |
| L0 非同步挑戰 | 每日題目＋「挑戰連結」：把題目種子和你的成績、步驟編進網址，朋友點開就是同一題，結束時比較成績、可看你的解法重播 | 不需要 | G001、G003先加 |
| L1 同裝置雙人 | 一台手機或平板輪流玩，親子同玩的主力 | 不需要 | 小島佔地王 |
| L2 好友即時對戰 | 建房間取得6碼（或QR code），朋友輸入加入；房間10分鐘沒人加入就失效 | 需要 | 小島佔地王→顏色實驗室對決→怪獸方塊大作戰 |
| L3 公開快速配對 | 和隨機玩家配對 | 需要 | **暫緩**，等安全審查與兒童實測 |

L0的挑戰連結只用網址片段（`#`後面）帶資料，不會送到伺服器，完全靜態、免費，而且能分享到LINE群組，是最便宜的「對戰感」。

## 候選遊戲

### A. 小島佔地王（回合制策略，8歲以上、大人也耐玩）

- **玩法**：6×6的小島格子地圖，兩人輪流放一片「路徑」（直線、轉角、T字三種，每回合從3片中選1片）。誰的路徑把一塊區域圍起來，那塊地就插上他的旗子，而且可以再走一步。地圖上有寶箱格，圍到加分；岩石格不能放。地圖格子放滿就結束，旗子多的人贏。
- **好玩在哪**：規則一句話講得完，但「要不要先圍小塊地、還是佈局大塊地」有真正的策略深度，大人小孩都能玩，最後一回合常常逆轉。
- **為什麼先做這款**：回合制不怕網路延遲，同一套程式能做對電腦（簡單／普通／困難三種AI）、同裝置雙人、線上好友對戰，技術風險最低。
- **兒童友善**：每回合沒有時間限制（線上可設60秒寬鬆計時，逾時自動幫他放最保守的一步）；小朋友模式用4×4地圖。

### B. 顏色實驗室對決（同題競速，6歲以上）

- **玩法**：直接沿用G003《顏色實驗室》的規則與關卡產生器。雙方拿到同一個種子產生的同一題，比誰先完成；同時完成時，步數少的人贏。三戰兩勝。
- **對手畫面**：只顯示對手的進度條和已完成的試管數，不顯示對方盤面，避免照抄。
- **好玩在哪**：小朋友熟悉的玩法，加上「對手快完成了！」的緊張感。
- **成本最低**：規則現成，伺服器只要轉送進度、驗證最後的步驟序列。

### C. 怪獸方塊大作戰（即時消除對戰，7歲以上）

- **玩法**：各自一個6×8的怪獸方塊盤面，交換相鄰方塊，三個以上同色連成一線就消除，上面的方塊掉下來可能形成連鎖。連鎖會往對手的盤面送出「瞌睡雲」：雲會蓋住格子，旁邊有消除時雲就會醒來、變回普通方塊。盤面頂端被塞滿就輸；或90秒後比分數。
- **翻盤機制**：被送雲越多，自己的下一次連鎖加成越高；雲落下前有1.5秒預警，可以搶先消除抵銷。
- **網路設計**：雙方各自在本機模擬自己的盤面，只把「我產生了多少攻擊」傳給伺服器。伺服器用相同的亂數種子和雙方的操作紀錄重算一遍，驗證後才把雲送過去；雲本來就有1.5秒預警，100–300ms的網路延遲玩家感覺不到。
- **原創性**：用交換消除，不做落下方塊；名稱、角色、音效、規則細節自行設計，不模仿既有品牌的方塊遊戲或其外觀。

### D. 記憶怪獸翻翻樂（回合制，4–6歲、親子）

- **玩法**：翻牌配對，但配對成功的怪獸會跳到旁邊的牌堆，偶爾兩張牌互換位置（有動畫提示），讓大人不會穩贏。
- **對象**：學齡前，全程圖示與配音，不需要識字。主要是同裝置親子玩，線上好友房間是附加功能。

### 跨遊戲：每日挑戰與挑戰連結（L0）

G001、G003等現有遊戲加入「今日題目」（以日期為種子，全球同一題）與「挑戰朋友」按鈕。不記連續天數，漏玩沒有懲罰。

## 線上架構（L2）

### 元件

- **同一個Cloudflare Worker**（`game-lab`）加上Worker腳本，`assets.run_worker_first`只設`["/api/*"]`：靜態資源維持免費、不經過Worker；只有`/api/*`的對戰請求進Worker。這是[DEPLOY.md](DEPLOY.md)「不寫Worker腳本」的唯一例外。
- **Durable Object `Room`**：一個房間一個實例，用`idFromName(房間碼)`定址；負責收雙方的WebSocket、跑共用規則、驗證、廣播。必須用**WebSocket Hibernation API**（`ctx.acceptWebSocket`），閒置時不計時間費用。
- **客戶端**：[partysocket](https://github.com/cloudflare/partykit)（MIT，1.x）處理斷線重連與訊息緩衝。伺服器端直接用Durable Objects原生API；PartyServer目前0.5版、README標示仍在開發中，先不採用。
- **規則套件**：每款對戰遊戲一個`packages/<game>-rules`，純TypeScript、無DOM，同時被遊戲與Worker引用；所有隨機性來自房間種子。

### 房間流程

1. 建房：`POST /api/rooms` 回傳6碼房間碼（排除容易混淆的0/O、1/I），與房間的WebSocket網址。
2. 加入：朋友輸入房間碼或掃QR code。滿2人才開始，房間碼立即失效，第三人無法加入。
3. 對戰：回合制由伺服器判定每一步是否合法；即時制由伺服器驗證攻擊。所有訊息都有版本號與序號。
4. 斷線：保留30秒等重連，期間對手畫面顯示「等待中」；超過時間就判對手勝，或讓斷線方改由AI接手（依遊戲而定）。
5. 結束：結果只回傳給雙方。房間狀態在結束後5分鐘刪除，不留戰績、不留IP或裝置識別碼。

### 費用估算（2026-10-26查[Durable Objects計費](https://developers.cloudflare.com/durable-objects/platform/pricing/)）

- 免費方案可用SQLite後端的Durable Objects：每天10萬次請求、1.3萬GB-s時間，UTC 00:00重置；超過會直接報錯，不會自動收費。
- WebSocket建立連線算1次請求；收到的訊息以20:1計費（100則算5次）；送出的訊息不收費。開啟Hibernation後，閒置期間不計時間。
- 粗估一場3分鐘對戰約20次計費請求，免費額度每天約可撐5,000場。超過時前端收到錯誤，就改成提示「線上對戰今天客滿，先和電腦玩」。
- 上線後在Cloudflare後台看實際用量，再決定是否要升級到付費方案（每月5美元起）。

### 兒童安全與隱私

美國[COPPA修正案](https://www.federalregister.gov/documents/2025/04/22/2025-05904/childrens-online-privacy-protection-rule)2025-06-23生效，2026-04-22起全面適用：個資範圍包含兒童的聲音錄音等。本設計的對策：

- 不蒐集任何個資：沒有帳號、名字、Email、文字或語音聊天、照片、定位。
- 暱稱從固定怪獸名稱表隨機產生（例如「藍色跳跳怪」），每場都換。
- 互動只用8個預設貼圖（讚、哈哈、再來一局……），每5秒最多送1個，可以一鍵關閉對手的貼圖。
- 房間碼只在當場有效，不存好友名單。
- 不使用跨場次的持久識別碼；每場只產生臨時的連線ID，房間結束就刪掉。
- **L3公開配對上線前**，要先請熟悉兒童隱私的法律顧問看過，並更新隱私說明。本文件不構成法律意見。

## 測試與驗收

- 規則套件：vitest單元測試，包含AI對AI自動跑1,000局，檢查不會卡死、先手勝率在45–55%之間（太偏就調整規則）。
- Worker與Durable Object：用`@cloudflare/vitest-pool-workers`在本機模擬兩個客戶端連線，測建房、加入、第三人被拒、斷線重連、逾時判勝、非法操作被拒。
- 網路延遲：在測試中加入200ms與800ms延遲，確認即時對戰不會不同步、回合制不會重複出手。
- 費用：用機器人連打100場，從Cloudflare後台記下實際請求數，回填上面的估算。
- 每款上線前，比照GAME_DESIGN.md的兒童驗收：手機與平板實測，找親子實際玩過。

## 建議實作順序（本輪只做1–4，皆不需後端）

1. **L0**：G003加每日挑戰與挑戰連結。一兩天可完成，也是測試「大家愛不愛跟朋友比」最便宜的方法。
2. **A 小島佔地王**：對電腦（三種難度）＋同裝置雙人。
3. **D 記憶怪獸翻翻樂**：同裝置親子玩法，學齡前可玩。
4. **B 顏色實驗室對決**：先做同裝置分割畫面（平板左右各一人）與挑戰連結版的「同題競速」，線上版之後再說。

暫緩，等有玩家數據與商業模式後再評估：

- L2好友即時對戰（`/api/*` Worker、`Room` Durable Object）。
- **C 怪獸方塊大作戰**：好玩但最適合線上即時，暫不做；若之後做，可先出對電腦版本。
- L3公開配對：除了上述條件，還要完成兒童隱私的法律審查。

## 商業模式保留彈性

目前的設計不會綁死任何商業模式：沒有帳號與個資，日後要做家長付費解鎖、學校／補習班授權、品牌合作關卡都還有空間。要注意的是兒童網站的廣告限制很多（例如COPPA對追蹤式廣告的規定），如果日後考慮廣告，要先查清楚再設計，不要先在遊戲裡預留廣告位。
