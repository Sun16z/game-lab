# G001 完美疊塔：家庭對戰版規格

2026-11-03｜Claude 撰寫，交 Codex 實作，Claude 審。背景：Justin 觀察 game-lab 多數遊戲可玩性不足，女兒只對完美疊塔有興趣；機制本身容易被複製，決定先收斂到完美疊塔，把它做成「全家一起玩」的遊戲。

## 要驗證的假設

孩子願意一玩再玩的理由是「有一個她在乎的人在等她超過」。完美疊塔已經有「差一層破紀錄」的張力；把對手從「自己的最佳成績」換成「爸爸的 23 層」，重玩意願會明顯提高。

成功標準（兩週內）：

| 指標 | 怎麼量 | 門檻 |
| --- | --- | --- |
| 孩子自發重玩 | 觀察測試：不提示，她主動開第幾局 | 單次 ≥ 5 局 |
| 回傳挑戰 | 收到挑戰後 24 小時內傳回一個挑戰 | ≥ 1 次／天，連續 3 天 |
| 挑戰連結被打開後真的玩 | 分析事件 `challenge_open` → `run_start` | ≥ 60% |

達不到就停在這一版，不再往上加功能。

## 範圍：三件事

### 1. 家人挑戰連結（主角）

- 結算畫面主要按鈕改成「傳給家人挑戰」。
- 第一次按會出現「你是誰」：一排角色按鈕，**不需要打字**：爸爸、媽媽、哥哥、姊姊、弟弟、妹妹、阿公、阿嬤、我。每個附朵朵世界的頭像（沿用 `WIND_CHIME_ISLANDS_BRAND.md` 素材）。選過就記在本機，之後可在設定改。
- 產生連結：`?c=<layers>&r=<role>&s=<seed>&m=<mode>`。
  - `c`：整數 0–999；`r`：上面角色清單的 key；`s`：這一局的 seed；`m`：`standard` 或 `child`。
  - 不放名字、不放任何個資；不經過任何伺服器。
- 開啟連結的人看到：大頭像加一個大數字（「爸爸 23」），下面一個按鈕「我要超過」。
- 這一局用同一個 seed、同一個模式，所以兩個人疊的是同一座塔。
- 遊玩中，在第 23 層的高度畫一條虛線，旁邊放爸爸的小頭像。越接近，線越亮，配一個短音效。這是整個功能最重要的一個畫面。
- 超過時：在那一層放小慶祝（遵守 `2026-10-31` 決策：特效不碰操作區、≤0.8 秒、同時只一個），結算顯示「超過爸爸了！」，主要按鈕變成「傳回去給爸爸」。
- 沒超過：結算顯示「差 3 層」，主要按鈕是「再一次」，次要按鈕才是分享。
- 參數不合法（超出範圍、角色不在清單、seed 格式不對）就當成一般遊戲開始，不顯示錯誤。

### 2. 今日塔

- 準備畫面加一個「今日塔」入口。seed 固定為 `daily-YYYY-MM-DD`，日期用玩家本機日期。
- 每天每人只記一個「今日最佳」；可以無限重玩。
- 今日塔的挑戰連結一樣帶 seed，所以不同時區的家人也是同一座塔。
- 「今天全家」小榜：只列本機收到或傳出過的今日挑戰（角色＋層數），存在本機，隔天清空。不做線上排行榜。

### 3. 朵朵貼紙簿

- 9 張貼紙，達成就解鎖，存在本機：第一次傳挑戰、第一次超過家人、被超過後再超回來、今日塔連續 3 天、今日塔連續 7 天、單局 5 次 Perfect、單局 20 層、單局 50 層、集滿前 8 張。
- 準備畫面右上角一個貼紙簿按鈕；解鎖當下在結算畫面顯示新貼紙，不打斷遊玩。
- 沿用既有霓虹／星際主題解鎖，不另加貨幣或抽獎。

## 不做

- 帳號、登入、線上排行榜、聊天、任何後端。
- 文字輸入（孩子不用打字）。
- 廣告、內購、抽獎、每日登入獎勵的壓力設計。
- 改動原本的分數規則、Perfect 判定與難度曲線（家庭對戰用同一套規則）。

## 技術要點

- `rules.ts` 已有 `startPhaseForLayer(layer, seed)`、`main.ts` 的 `paletteFor(seed, theme)`：挑戰與今日塔只要把 `run.seed` 換成指定 seed，塔就一樣。確認 `speedForLayer` 等其他隨機來源也只依 seed；若有其他 `Math.random` / `crypto.randomUUID` 影響塔形，要改成由 seed 推導。
- 新增純函式模組（例：`challenge.ts`）：`encodeChallenge`、`parseChallenge`（含所有驗證）、`dailySeed(date)`；全部有單元測試。
- 本機儲存沿用 `game-storage` 介面，新增 key：`g001.role`、`g001.daily.<date>`、`g001.family.<date>`、`g001.stickers`；讀不到時（隱私模式）照常可玩。
- 分享沿用 `@game-lab/game-share` 的 `shareLink` / `shareCardOrDownload`；成績圖卡加上角色頭像與「換你」。
- 分析事件沿用既有介面：`challenge_create`、`challenge_open`、`challenge_beat`、`daily_start`、`sticker_unlock`；不送角色以外的任何資訊。
- 九種語系都要有：角色名稱、挑戰文案、今日塔、貼紙名稱；角色稱謂請依各語系自然用法（例如西語 abuelo/abuela），母語審核列入既有待辦。
- 兒童模式（`m=child`）的挑戰連結只能在兒童模式下開啟同一座塔。

## 測試與驗收

- 單元測試：連結編碼／解析（合法、每種不合法、邊界 0 與 999）、同一 seed 兩次產生相同的起始相位與配色、今日 seed 隨日期變、貼紙解鎖條件。
- 瀏覽器實測：手機直式；開挑戰連結→看到大數字→玩到虛線→超過→傳回；隱私模式下仍可玩。
- **兒童觀察測試（Justin 做，最重要）**：不先解釋規則，把爸爸的挑戰連結給女兒，觀察 10 分鐘。記錄：主動開了幾局、看到虛線時的反應、超過時的反應、有沒有說「我要傳給爸爸」、在哪一步卡住。結果寫回本文件末尾。

## 交付順序

1. 挑戰連結＋虛線（可單獨上線測試）。
2. 今日塔＋今天全家。
3. 貼紙簿。

每一步都開 PR 並加 `auto-review` 標籤，走本機審查迴圈；合併由 Justin 按。
